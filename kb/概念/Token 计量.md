# Token 计量

> [!info] 一句话定义
> Token 是 LLM 的计量单位（≈子词），既决定**费用**（输入+输出分别计价）也决定**上下文预算**（窗口占用 = 系统提示+历史+工具结果+当前问题）。

## 🎯 核心概念

### 是什么
- 分词器（BPE 类）把文本切成子词单元：英文 ≈ 0.75 词/token，中文常见 1 字 ≈ 0.6~1 token（因模型而异）
- 计费 = 输入 token 单价 × 输入量 + 输出 token 单价 × 输出量（输出通常贵数倍）
- Agent 的轨迹会**复利式**消耗：每一轮都携带全部历史，O(n²) 增长

### 为什么重要
- 成本预估与限流设计的基础（速率限制也按 token 计）
- 上下文工程的前提：记忆回填、RAG 片段、工具输出都要在预算内取舍
- 来自 [[PITFALLS-GUIDE]] 第三篇：把 token 当字数估算是新手第一大坑

## ⚠️ 易错点 & 陷阱
- ❌ 常见误解：中文一个字就是一个 token、token 等于字数
- ✅ 正确理解：以具体模型分词器实测为准；结构化输出（JSON schema）本身也占 token
- ❌ 只盯输出费用？→ 长对话 Agent 的账单大头往往是反复重发的输入历史

## 🃏 闪卡（Spaced Repetition）
#flashcards/ha/避坑

Agent 长对话的 token 消耗为什么是近似平方级？::每轮都携带全部历史重发，n 轮累计输入 ≈ O(n²)

输出 token 为什么比输入贵？::生成需要逐 token 自回归推理，算力远高于一次性编码输入（各家定价通常贵 3-5 倍）

中文 token 的正确估算姿势？::不背换算表，用目标模型的 tokenizer 实测；不同模型分词器差异很大
